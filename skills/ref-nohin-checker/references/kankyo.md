# ネットに出られない環境・チェッカーが無い環境での扱い

SKILL.md の 1・3・4 から読む。ふだんの環境(ネットに出られ、チェッカーがある)では要らない。

## 1. ネットに出られない環境

- 接続を拒まれる・時間切れの形では、各段階が「測れなかった」(未検査)に落ち、段階Cの一覧の当てたページには「取れていない」と出る。扱いは SKILL.md の 3(チャットに一覧を出してユーザーの判断を待つ)。
- 名前(ドメイン)が引けない形では、段階Aが全リンクを「リンクが届かない」の違反(✕)に数える。
  - そのリンクは、直さない・消さない(ネットに出られないだけで、リンクの誤りとは限らない。「違反(✕)をゼロにしてから納品する」をこのリンクに当てない)。
  - そのときも台帳は渡さず、画面の段階Aの ✕ の行(段階・行・リンク・理由)を1件も落とさずにチャットの一覧に並べ、ユーザーの判断を待つ(画面が「…ほか n件」で切れていたら `--max-findings 0` を付けて全件を出す。リンクの誤りとは限らないので、どう扱うかは作る側では決められないため。ユーザー裁定 2026-09-28)。

## 2. チェッカーが無い環境で貼る申告の3行

段階ごとに、同じ印(「stage-a v1」など)の囲みで次の3行を貼る(SKILL.md の 4-1 の「囲みを空にしない」)。

| 段階 | 3行 |
|---|---|
| A | 「★事実の関門 段階A —— ★チェッカーを走らせていない環境で作った納品物である」/「・★リンクが現に届くかは、1本も確かめていない(段階Aを走らせていない)」/「・★これは「0件だった」ではない。「確かめていない」である」 |
| B(run-bunken-daicho だけ) | 「★事実の関門 段階B —— ★チェッカーを走らせていない環境で作った納品物である」/「・★書誌が登録機関の記録と合うかは、1本も確かめていない(段階Bを走らせていない)」/「・★これは「0件だった」ではない。「確かめていない」である」 |
| C | 「★事実の関門 段階C —— ★チェッカーを走らせていない環境で作った納品物である」/「・★引いた逐語が原典に現に在るかは、1本も確かめていない(段階Cを走らせていない)」/「・★これは「0件だった」ではない。「確かめていない」である」 |
