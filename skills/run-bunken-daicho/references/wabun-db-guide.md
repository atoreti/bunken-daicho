# 和文DB攻略台帳(育てる台帳)

このスキルの差別化の核。各DBの〈検索URLの型/直読可否/得意分野/技〉を蓄積する。**エントリは実アクセスで実証してから「実証済み」節に置く**(記憶でエンドポイントを書かない=鉄則の開発自体への適用)。未実証は「候補」節に置き、使う前にそのセッションで直読可否を確かめる。**台帳づくりの工程7 の追記の提案は、確かめ役 `assign-bunken-guide-evaluator` の確かめで「足せる提案」になった物だけを「実証済み」節に足し、確かめられなかった提案は「候補」節に置く**(提案した会話の記憶や読み違いで、実在しない欄の名前が2件入ったことがあるため。e-Stat の節の「提供年月」。SKILL.md §2-7)。

## 検索語設計(表記ゆれ展開) — 和文献検索の核心技

和文DBは表記に厳密で、**同じ概念でも表記が違うだけで0件になる**。探索の前に必ず2〜4表記へ展開する:

- 漢字/ひらがな/カタカナ: 椎茸/しいたけ/シイタケ
- 送り仮名・複合語の切り方: 乾しいたけ/干し椎茸/乾椎茸/乾燥しいたけ
- 専門語/一般語/法令用語: 直売所/ファーマーズマーケット、特用林産物(法令・行政用語)
- 新旧名称: 省庁再編・学会名変更の前後

**0件・低ヒットは「文献がない」ではなく「表記が合っていない」をまず疑う**。実証例: CiNiiで「乾しいたけ ビタミンD」が0件→直読困難と誤診しかけたが、実際は表記の問題で、CiNii自体は直読可能だった(2026-07-19解明)。

### 検索語の並べ方(F-125・2026-08-17実測)

**同じ語でも、並べ方(語数・区切り・順序)だけで0件になったり件数が桁で変わったりする。**表記ゆれ展開とは別の軸なので、両方やる。

- **語数を減らして投げ直す**(3語→2語→1語)。実測: CiNii「訪問看護ステーション 多職種連携 促進要因」**0件** → 2語「訪問看護ステーション 多職種連携」**122件** /
  「冷や汁 観光」**0件** → 1語「冷や汁」**18件**
- **同じ語のまま別DBへ投げ直す**(→下の「罠」の0件誤診)。実測: CiNii で0件だった3語を J-STAGE へそのまま投げると **7件・4件・47件**
- ★**0件の表示を「その語では文献が無い」と読まない。**J-STAGE のタイトル/抄録限定検索のURL型では、
  **検索が実行されず詳細検索フォームが返ってくることがある**(実測: 53回の呼び出しで件数の表示が0回)。
  ★★**何が引き金かは分かっていない**——**1語(冷や汁)でも起きたし、別の1語(農泊)では19件が返った。機序は未確定なので、条件を推測で書かない。**
  分かっているのは**対処**だけである: **結果に件数の表示が見当たらないときは、0件と記録する前に、
  ①語数を変える ②全文検索(globalSearchKey)に切り替える ③同じ語で別DBに投げる——のどれかを実際にやってから判断する**
- **投げた形をそのまま探索記録に残す**(語の並びが違えば別のクエリである)。
  ★**「(結果なし、または取得不可)」のように、0件なのか検索できなかったのかを区別しないまま書かない**——実運用の探索記録にこの書き方が実在した。**確かめてから書く**

## 発見と本文到達の役割分担(2026-07-19正典化)

- **発見**: J-STAGE+CiNii併用。CiNiiは紀要・図書・博論の網羅に強く、発見から外さない
- **本文到達・入手状況の確定**: 必ず**本文提供側ページ**で行う——J-STAGE記事ページ(アクセス種別表示)・機関リポジトリの本文ページ。**CiNii/NDLは書誌の索引であり本文の在り処ではない**(書誌ページの記載から全文OAを推定した3ランが検証で不合格になった実証あり)
- **台帳のリンク優先順**: DOI/J-STAGE記事ページ > リポジトリ本文ページ > crid(書誌確定の補助)

## 本文PDFの読み取り(F-020・2026-08-17に実在の和文論文PDF5本で実証)

本文に**到達**したあと、その中身を**読む**ための手順。台帳の精読欄(本文精読済み/抄録どまり)はここで決まる。
(統計原表 Excel の読み取りは下の e-Stat の節にある。PDF はここ)

**手段の順序(実測で決めた。合成検体ではなく実在の和文論文PDF 5本の結果)**:

1. **PyMuPDF(`import fitz` → `doc[i].get_text()`)を既定にする** —— 5本中4本を正しく読めた。速く導入も軽い
2. 入らない環境では **pdfplumber** か **pdfminer.six**。抽出できた日本語の文字数は PyMuPDF と完全に一致した(同点)
3. **pypdf は和文の本文抽出に使わない** —— ★**静かに化ける**。5本中2本で 7,636字・9,137字という「それらしい分量」を返しながら**日本語が1文字も無かった**。字数を見ても気づけない
4. **pdftotext(poppler)も和文では当てにしない** —— 同じ2本で3字しか返さなかった(失敗は分かりやすいが読めていない)

**★文字化けの検知は「日本語の割合」だけではすり抜ける。「書誌の題名が出るか」で行う**:

抽出したテキストに、**その文献の題名の一部(書誌欄で確定済みの文字列)が現れるか**を必ず確かめる。
理由: 5本中1本は**本文は読めるのに題名・見出しだけが別の文字に化ける**(埋め込みフォントの対応表が欠けた PDF)。
日本語の割合は 85% あり、割合による検知はこれをすり抜けた。題名の照合は**5本すべてで正しく判定できた**。

**★化けを検知したら精読フラグを格上げしない。** 読めた部分だけで要旨を書き、精読欄は**「抄録どまり」**のままにする。
入手状況が「全文OA」でも同じ(実際より読めている風への格上げはゼロ許容違反 → daicho-format.md)。
**「文字化けしました」と言ってこないことは、読めたことの証明にならない。**

**どの手段でも読めないとき(実測で5本に1本)**: テキスト層が無いスキャンPDF・対応表の壊れた埋め込みフォントが原因で、
抽出では解決しない。**OCR(画像の文字を読み取る処理)へ退避する**——姉妹スキル **run-uradori** が同型の退避を持っており
(`run-uradori/references/daicho-format.md` の「受領」表の再取得の一手=「OCRをかける/原本のテキスト版を依頼する」、
`run-uradori/references/verification-playbook.md` の取得の技)、そちらの手順に合流できる。
OCR も行わない場合は、台帳では**「未入手」相当の扱いにせず**、入手状況はそのまま・精読欄を「抄録どまり」とし、
探索記録に「本文PDFはテキスト抽出不可(OCR要)」と残す。

## 統計・白書の扱い(2026-07-19正典化)

- **数値の一次データは統計表の原表(Excel/CSV)を優先**(e-Stat・省庁統計ページ)。白書・報告書PDFは原表の要約・加工物であり、文脈・解釈の出典として使う(両方載せる場合は台帳で種別を分けて区別)
- 原表Excelで確保できた統計は run-excel-graph(集計・グラフ)へ直結できる——引き継ぎ案内で一言添える
- e-Stat直叩きは実証済み(実証済み節参照)——統計表検索`stat-search/files?query=`から原表Excel直リンクへ1手で到達できる。省庁の統計ページ経由は補助ルート
- **統計の年代ゲートは結果一覧の「調査年月」で判定する(A-5・2026-07-20/F-109で欄名を訂正 2026-08-17)**: 文献はURLパラメータで年を絞れる(CiNii `from/until`・J-STAGE `yearfrom/yearto`)が、**統計にはその仕組みが無く、結果一覧の欄を読んで絞る**。実装場所が文献=URL・統計=結果読解で非対称なので迷いやすい。年代ゲートの特則(2026-07の検証計画で確定)「統計・調査は**最新の調査年**を終点に10年遡る」(例: 最新の調査年が2024年なら2015〜2024)は、この**調査年月**の読解で運用する
  - ★**「提供年月」という欄は e-Stat に存在しない**(2026-08-17実証: 結果一覧の全ページ・API仕様書とも出現0回)。**旧版の記述は誤りだったので使わない。**実在する列見出しは逐語で **「政府統計名 / 提供統計名・提供分類 / 調査年月 / 公開(更新)日 / 表示・ダウンロード」**
  - ★**『調査年月』(いつ調べたか)と『公開(更新)日』(いつ公開されたか)は別物で、同じ行でも数年ずれる。**採るのは**『調査年月』**。境目にある統計表が入ったり外れたりするので、**どちらの欄を読んだかを台帳に必ず書く**(→ daicho-format.md「統計原表行の追加メタ」)
  - 「新しい技・罠の追記を提案する」(SKILL.md §2-7)を使うとき、**この欄名に関する追記は特に慎重に**——過去に「単表ページで提供年月を確認できる」という**実在しない欄の記述を追記提案した実例が2件ある**(記録に残るのは、2026-07-20 の試走で台帳の列と手引きの文に「提供年月」を入れた2件の提案)。欄名は必ず結果一覧の見出しの逐語と突き合わせてから提案し、工程7 の確かめ(`scripts/teian.py`)に通す

## 実証済み(実アクセスで直読確認)

### J-STAGE ★主力(2026-07-18実証)
- **検索URL型**: `https://www.jstage.jst.go.jp/result/global/-char/ja?globalSearchKey=<検索語をURLエンコード>`
- **直読**: 可。結果ページから論文タイトル・著者・誌名・巻号頁・DOI・フリー(OA)表示が読める
- **記事ページ**: `_article/-char/ja` 形式で書誌+抄録。**書誌確定はこのページで行う**
- **得意**: 国内査読論文・学会誌
- **技**: 全文検索のため無関係な号(総会要旨集等)が混じる。タイトルで関連性を判断する
- **査読の有無を確かめる手筋(F-019・2026-08-17実証)**: 誌の**資料トップ** `https://www.jstage.jst.go.jp/browse/<誌略号>/-char/ja` を開くと、ISSN(雑誌ごとの国際番号)の直後に **「ジャーナル 査読 フリー」** の帯が出る。**この帯に「査読」の語があれば査読あり**、無ければ査読の表示が無い誌である(実証: amsj〈農業市場研究〉・arfe〈農林業問題研究〉・chiikikeizai〈地域経済学研究〉・arp1982〈農業経営研究〉の4誌で「査読」あり / ajg〈日本地理学会発表要旨集〉・jfs〈日本林学会大会発表データベース〉の2誌は**帯に「査読」の語が0回**)。誌略号は記事URL `/article/<誌略号>/…` から取れるので**1手**で見に行ける。表示が無い誌の文献は「査読論文」と書かず退避語彙**「学会誌(査読不明)」**を使う(→ daicho-format.md「種別『査読論文』の確定手続き」)
- **タイトル/抄録限定検索(2026-07-20実証)**: `https://www.jstage.jst.go.jp/search/global/_search/search/-char/ja?item=<番号>&word=<語>&yearfrom=YYYY&yearto=YYYY`。item: 1=資料タイトル/2=論文タイトル/3=抄録/4=全文/5=キーワード/8=著者名/9=著者所属。全文検索(globalSearchKey)で無関係号が混じるときは**item=2(論文タイトル)で精度**、**item=3(抄録)で網羅と精度の中間**を取る。年範囲も同URLで指定可
- **古い記事の記事URL(2026-09-05実証)**: 新しい記事は DOI の接尾辞から記事URLを組み立てられる(例 `10.20818/jfe.68.1_28` → `/article/jfe/68/1/68_28/`)が、**電子化された古い記事は `<巻>_KJ<数字>` という別形式**で(例 `/article/rinrin/38/6/38_KJ00009060464/`)、**DOI から組み立てたURLは HTTP 500 を返した**(実証: 林業経済 1985・1989年の記事)。**古い記事は DOI(`https://doi.org/…`)を開いて、リダイレクト先の記事URLを受け取る**
- **★短い時間の大量の自動接続を締め出す(2026-10-20 実測)**: 試験で台帳づくりを3本並べて回すと、30分〜1時間40分で、この PC からの接続を要求の直後に切られるようになった(curl の終了コード 56・ECONNRESET。同じ時に JST の本体・CiNii は開けた)。公衆の Wi-Fi でも自宅の回線でも起き、少なくとも3時間続いた。その間は、同じ PC のブラウザでも J-STAGE を見られなかった
  - **防ぎ方**: `scripts/kensaku.py` は J-STAGE に6秒以上あけて1本ずつ投げ、切られたらその回はもう投げない。この形にした後の試験(2026-10-21〜11-01。2〜3本を同時に回した55回・J-STAGE の検索468本)では、切られた検索は0本だった。記事ページ・誌トップも、間をあけて1件ずつ開く
  - **切られたら**: その回は記事ページ・PDF も開かず、書誌の確定は DOI のページか CiNii で行い、J-STAGE だけにある文献は探索記録に残す(SKILL.md 工程2)
  - **原因は外から見分けられない**: 2026-10-21 は大学の回線から同じ形で切られた(JST の本体・CiNii は開けた)。締め出しか回線かを見分けず、どちらでも同じ扱いにする
  - **規約**: 閲覧規約(https://www.jstage.jst.go.jp/static/pages/TermsAndPolicies/ForIndividuals/-char/ja 。2026-11-01 に読んだ)は、過度な負荷をかける行為と、機械的な手段で登載データを大量にダウンロードする行為を禁じ、その時は利用を停止・制限できると定める

### CiNii Research ★主力(2026-07-19実証)
- **検索URL型**: `https://cir.nii.ac.jp/all?q=<検索語をURLエンコード>`
- **直読**: 可。ヒット件数・タイトル・著者・誌名・年が読める(実証: 「地域活性化」14,851件・上位書誌取得)
- **書誌確定**: 各文献の詳細ページ(`cir.nii.ac.jp/crid/...`)で行う
- **得意**: 紀要・学会誌・図書・博士論文を横断する国内最大級の学術検索。J-STAGEに無い紀要類に強い
- **技**: 0件のときは表記ゆれ展開してから判断(上記の実証例)。著者検索で芋づる(KAKENで研究者を特定→CiNiiで著者名検索)が有効
- **注意**: cridページの「リポジトリリンクあり」等の記載から入手状況を推定しない。本文提供側ページ(リポジトリ本文ページ等)に実アクセスして確定する(役割分担の節を参照)
- **種別絞り込み(2026-07-20実証)**: 論文のみ=`/articles?q=`・図書=`/books?q=`・博士論文=`/dissertations?q=`(全種別=`/all?q=`)
- **年代範囲(2026-07-20実証)**: `&from=YYYY&until=YYYY`(YYYYMM可)。実測: 「道の駅」論文1,709件→2020〜2022指定で257件。**確認ゲート項目3「年代範囲」はこれで実装する**
- **通常の検索URLが空で返るとき(2026-09-05実証)**: 取得の手段によっては `/all?q=`・`/articles?q=` の本文が空で返り、件数も一覧も読めないことがある。そのときは同じ語を **OpenSearch API**(アプリケーション ID の `appid` が要る。規約の手続きで、2026-10-31 までは ID 無しで使っていた)`https://cir.nii.ac.jp/opensearch/all?q=<検索語をURLエンコード>&format=json&count=20&appid=<ID>` へ投げると、総件数と書誌一覧が JSON で直読できた。**この一覧は発見用であり、書誌の確定は従来どおり詳細ページ(`cir.nii.ac.jp/crid/...`)で行う**。種別版の API(`/opensearch/articles`・`/books`・`/dissertations`)も、`from`・`until` を付けて総件数と一覧が JSON で取れた(2026-10-20 実証。博士論文は `dc:identifier` に `cir:DOI` を持つものがある)。`scripts/kensaku.py` の `--db cinii` はこの API を使い、ID はユーザーの環境変数 `CINII_APPID` から付ける(記録には ID の無い URL を残す)
- **詳細ページの JSON(2026-10-20実証)**: `https://cir.nii.ac.jp/crid/<番号>.json` で、題名(ja・en・読み)・著者・誌名・巻・頁・年が項目で取れる。★出版社の欄に `dummy publisher` と入っている例があった(その値は書誌に写さない)

### KAKEN(科研費) (2026-07-19実証)

- **技**: 成果報告書ページには発表文献リストがあり、芋づるの起点になる

### 英語のデータベース(和主英従・既定) (2026-11-02実証・claude-harness の docs/user-decisions.md の D75)
4つとも `scripts/kensaku.py … sagasu --db openalex|semanticscholar|arxiv|crossref` で送る(検索の記録と候補の一覧に入る)。語は英語に訳して送る。同じ DB への問い合わせは PC 全体で1本ずつにし、前の問い合わせから間をあける(下の秒数)。断られた(HTTP 429)時は2・4・8秒(arXiv は3秒ずつ)待って3回まで送り直し、だめなら「断られた」と1行残して、同じ語をほかの英語の DB に送る。**ブラウザでページを開いて代わりに探さない**(枠や間合いを越えることになるため)

#### OpenAlex(英語の論文の索引。主)
- **検索URL型**: `https://api.openalex.org/works?search=<語>&per_page=<件数>&page=<頁>&select=…`(題名だけは `filter=title.search:<語>`。年は `filter=from_publication_date:YYYY-01-01,to_publication_date:YYYY-12-31`)。件数は100まで
- **直読**: 可(JSON)。件数は `meta.count`。実測: 「sport tourism economic impact」で 62,391件(2015年以降)。日本語の語でも和文の論文が返る(2026-10-21)
- **キーと1日の枠**: キー無しでも使える。枠は金額で数え、語の検索1回 $0.001・キー無しの1日の枠 $0.10(応答の欄 `X-RateLimit-Cost-USD`・`X-RateLimit-Limit-USD`)。キー無しの枠は同じ回線から使う人みんなで分け合う。無料のアカウントのキーで1日 $1(支払いの方法は要らない。公式の値段のページ)。キーはユーザーの環境変数 `OPENALEX_API_KEY` に置き、スクリプトが要求の欄(Authorization)で送る(キーは openalex.org のサインインにも使うので、URL・記録・画面に出さない)。枠の残りは検索の記録の `waku_nokori_usd`
- **枠が尽きたら**: HTTP 429 で残りが0。その日(UTC。日本時間の朝9時に戻る)はもう送らない(スクリプトが止める)
- **技**: `open_access.oa_url` に無料で読める置き場(機関リポジトリ・arXiv など)が入る(候補の一覧の「無料で読める置き場」)。`is_retracted` が真の論文は撤回されている(採らない。スクリプトが止める)。DOI で1件を取るのは枠をほぼ使わない
- **注意**: 和文の論文の引用(参考文献の一覧)は少ない(和文14件中2件の例)

#### Semantic Scholar(英語の論文の索引)
- **検索URL型**: `https://api.semanticscholar.org/graph/v1/paper/search?query=<語>&limit=<件数>&offset=<始め-1>&fields=title,authors,year,venue,journal,externalIds,publicationTypes,openAccessPdf,url`(年は `year=YYYY-YYYY`)。件数は100まで
- **直読**: 可(JSON)。件数は `total`
- **断られやすい**: キー無しは全員で分け合う枠で、混むと HTTP 429 になる(実測: 2026-10-21 は1回目で 429/2026-11-02 は1回目は通り、同じ日の後の回は3回送り直しても 429)。断られた時は OpenAlex・Crossref に同じ語を送る
- **出典の表示**: 約款の Attribution の節が、使って得た物を載せる所に Semantic Scholar の出典を書くよう求める(2026-11-02 に読んだ)。検索が答えを返した台帳は、探索記録の「使ったAPIと出典」に1行写す(daicho-format.md。`kensaku.py … tashikame` が確かめる)

#### arXiv(前刷り。機械学習・統計・計算の手法)
- **検索URL型**: `https://export.arxiv.org/api/query?search_query=all:<語1> AND all:<語2>&start=<始め-1>&max_results=<件数>`(題名は `ti:`・抄録は `abs:`。年は `submittedDate:[YYYY01010000 TO YYYY12312359]`)。スクリプトは語を AND でつなぐ(`--hoho shiki` は式のまま送る)
- **直読**: 可(Atom の XML)。件数は `opensearch:totalResults`。誤りの時も XML の項目で返る(スクリプトは失敗と記録する)
- **間合い**: 約款が「3秒に1本・同時に1本」を、使う機械の全部を合わせて求める(2026-11-02 に読んだ)。書誌の説明は CC0
- **得意と不得意**: 実測: 「sport tourism」0件・「tourism AND forecasting」58件。観光・地域の論点では、手法(機械学習・統計)の論点で出る
- **注意**: 査読を経ていない前刷りなので「査読論文」と書かない。出版された版(`arxiv:doi`・`arxiv:journal_ref`)があれば、その版で書誌を確かめる

#### Crossref(DOI の登録機関)
- **検索URL型**: `https://api.crossref.org/works?query=<語>&rows=<件数>&offset=<始め-1>&select=DOI,title,author,issued,container-title,volume,issue,page,publisher,type,URL`(書誌の欄だけは `query.bibliographic=`。年は `filter=from-pub-date:YYYY,until-pub-date:YYYY`)
- **直読**: 可(JSON)。件数は `total-results`。実測: 「sport tourism economic impact」で 3,868,507件(関連の順で、関係の薄い物も多く混ざる。上位を題名で見る)
- **間合い**: 名乗り無しの語の検索は1秒に1本・同時に1本(応答の欄 `x-rate-limit-limit: 1`・`x-concurrency-limit: 1`)。連絡先のメールは名乗らない(ユーザーの決定 2026-10-31)
- **書誌の確定に使う**: `https://api.crossref.org/works/<DOI>` で1件の書誌が JSON で取れる。出版社のページが機械の取得を断る論文の書誌は、ここで確かめる(下の罠)。題名に HTML のタグ(`<i>` など)が入ることがある(スクリプトは外して読む)

#### 抄録の取り寄せ(英語の論文)
- `kensaku.py <作業用フォルダ> shoroku --doi <DOI>` が Semantic Scholar → OpenAlex → Crossref の順に抄録を取り、出どころの URL と一緒に作業用フォルダの `shoroku/` に保存する(`--arxiv <番号>` は arXiv)。OpenAlex の抄録は語と位置の並びで返るので、スクリプトが文に戻す。実測: Taylor & Francis の論文(出版社のページは 403)の抄録を OpenAlex から取れた

## 罠(共通)

- **0件誤診の罠**: 0件をDBの不調・文献の不在と即断しない。①表記ゆれ展開 ②別DB、の順に必ず試してから「探索記録」に正直に残す
  - ★**②の「別DB」へ持って行くのは、まず【0件になったその検索語そのもの】である(F-059・2026-08-17)。**
    表記を変えた語だけを持って行くと、**元の語はどのDBにも一度も当たらないまま**「文献なし」に落ちる。
    実測: CiNii で0件だった3本の語を**表記も変えずそのまま** J-STAGE に投げると **7件・4件・47件**(うち2本は中身も論点に当たっていた)
  - ★**同じDBの中でも、検索方式を変えて当て直す。**J-STAGE なら全文検索(globalSearchKey)⇔ item=2(論文タイトル)/item=3(抄録)、
    CiNii なら `/all` ⇔ `/articles` の切り替え(上の各DBの節)
  - **どの語をどのDB・どの方式で投げたかを語ごとに探索記録へ残す**(DBごと2〜3クエリの目安の中で回す)
- 検索結果の書誌はそれらしく見えても、必ず詳細/DOIページを開いて確定する(スニペット書誌の禁止)
- 全文検索DBは無関係な号・巻がヒットする。タイトルで関連性を判断する
- ないものを作らない(捏造文献の禁止)。見つからない論点は「次の一手」つきで探索記録へ
- **英語の大手の出版社は、論文のページを機械で開くと断る(2026-11-02 実測)**: チェッカーと同じ名乗りで DOI を開くと、MDPI・Wiley・Taylor & Francis の3社とも HTTP 403 だった(3本とも Crossref に登録された実在の論文)。この論文は、書誌を DOI の登録の記録(Crossref など)で確かめて載せ、備考に断られたことを書く。入手状況・抄録・チェッカーで測れなかった時の扱いは daicho-format.md「英語の論文の行」(ユーザーの決定 2026-11-02)
- **IRDB横断検索は直読不可(2026-07-20負の実証)**: `irdb.nii.ac.jp/search` はHTTP 403(ブラウザUAでも不可=サーバ側ブロック)。代替: 発見はCiNiiで行い、リポジトリ本文へはCiNii詳細ページから各機関リポジトリの記事ページへ直接飛ぶ
