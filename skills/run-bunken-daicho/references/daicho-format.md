# 文献台帳の正典フォーマット

中身は台帳の JSON(<台帳名>.json)が正本で、人が見る HTML と、チェッカーと確かめ役が読む Markdown は `scripts/daicho.py` が作る(末尾の「台帳の JSON(正本)と、スクリプトが作る HTML・Markdown」節)。このファイルの Markdown の形は、スクリプトが作る機械用の写しの形で、列・語彙・要旨・抜き書き・帳尻・探索記録の決まりは、そのまま JSON の欄の決まりになる。
**コードの囲みは必ず閉じる**(行頭の ``` や ~~~ で始めた枠)。閉じていない囲みから後ろは、納品物チェッカー(ref-nohin-checker)が点検できず、合格にならない。
**台帳は UTF-8 で保存する**(Shift_JIS(日本語の古い文字コード)などで保存しない)。UTF-8 で読めない字を含む行は、納品物チェッカー(ref-nohin-checker)が点検できず、合格にならない。

## ヘッダーブロック(冒頭に必須)

```markdown
# 文献台帳: (テーマ)

- 目的: (何の執筆用か)
- 種別範囲: (確認ゲート項目2で承認された値をそのまま)
- 年代範囲: (同 項目3)
- 言語: (同 項目4)
- 件数目安: (同 項目5)
- エンジン: (同 項目6)
- 適合の基準: (同 項目7。台帳に載せる文献の条件を1文で)
- 論点1: (同 項目7。依頼の言葉をそのまま含む論点)
- 論点2(反論・限界): (同)
- 論点3(歴史・研究史): (同)
- 探し方(人と場): (同 項目7。中心の研究者と定番の学会誌。論点の外の1行)
- 実行日: 2026-07-18
```

**各項目は「キー: 値」の形で1行ずつ書く。**散文で「本台帳の目的は〜であり、実行日は〜」とまとめない
(人も点検プログラムもどの値がどのキーのものか拾えなくなる)。

### ヘッダーの宣言と本体の照合(F-021・2026-08-17)

**確認ゲートの承認値は書き換えずに写す。**実行中に方針を変えたなら、変えた事実ごと残す
(例: 「種別範囲: 査読論文のみ(承認) → 実行中に紀要まで拡大。理由: 和文の査読論文が2件しか無かったため」)。

**台帳を書き終えたら、本体がその宣言を満たしているか自分で照合し、結果をヘッダー直後か台帳末尾に1行で書く**:

- **種別範囲** — 本体の種別欄に宣言の範囲外の種別が無いか(『査読論文のみ』なら「学会誌(査読不明)」「紀要」「白書・報告書」が本体に無いか)
- **年代範囲** — 本体の年が宣言の範囲に入っているか
- **件数目安** — 実際の行数を数えて目安と比べる(超過しても落とさない → SKILL.md ゲート項目5)
- **論点** — どの論点にも、選別の帳尻の「採った」に行番号があるか、探索記録にその論点のブロックがあるか(→ SKILL.md の止めどき)

書き方の例:

```markdown
**宣言との照合**: 種別範囲=適合(全12件が査読論文) / 年代=適合(2015〜2024) /
件数=目安5〜10に対し12件(実在と適合を確定済みのため落とさず掲載) / 論点=4論点のうち3つに文献・論点2は探索記録へ
```

**食い違いがあったら黙って直さず、食い違いとその扱いを書く。**
読み手が序論に「査読論文のみを対象に12件を収集した」と書けるかどうかは、この1行で決まる。

## 論点と適合の基準(ゲート項目7)

**論点**は3〜6個。執筆で言いたいことの単位で、「どんな文献が要るか」が分かる形に書く(「〜を示した研究」など)。検索語を並べただけにしない(検索語だと、何が見つかれば足りたのかを後で判定できないため)。

- 毎回入れる3つ: 依頼の言葉をそのまま含む論点 / 「反論・限界」の論点 / 「歴史・研究史」の論点(テーマの経緯と転機、研究の移り変わり)。残りは依頼の目的(背景・方法・比較など)から立てる
- ヘッダーでは `論点1:` から番号を振り、反論・限界と歴史・研究史には `論点2(反論・限界):` のように種類を添える。同じ番号を選別の帳尻と探索記録の見出しでも使う(どの論点の話かを突き合わせられるように)
- **探し方(人と場)**は論点の外の1行(`- 探し方(人と場):`)。この分野の中心の研究者と定番の学会誌を書き、たどった後に、誰と何誌を中心と見たか、何で確かめたか(KAKEN の課題・J-STAGE の誌の一覧など)を書き足す。人と誌からたどる検索と、そこで採った文献は、その文献が答える論点の番号で記録する(選別の帳尻に人と場の行は無い)

**適合の基準**は1文。依頼が決めている対象・場所・時代・観点を書き、外す物があればそれも書く。場所は依頼が決めている時だけ書く(依頼が国内・特定の国と言っていなければ、「国内に限る」「海外だけの事例は外す」を書かない。海外の事例・文献にも、比べる材料や先行研究として使える物があるため)(例「スポーツイベント・合宿を事例に、開催地の経済・社会・観光への効果を扱った研究。競技そのものの研究は外す」)。種別・年代・言語はゲートの項目2〜4で決まるので、ここには書かない。

**途中で変えたとき**は、承認された文を消さずに、日付・新しい文・理由・見直した結果を書き足す(ヘッダーの宣言と同じ扱い。読み手が「何を基準に集めたか」を序論に書けるように)。論点を足す・変えるときも同じ形で残す:

```markdown
- 適合の基準: (承認された文) → 2026-10-20 変更: (新しい文)。理由: 国内の事例に限ると和文の研究が3件しか無かったため。見直し: 採った行は新しい基準にも合う・落とした候補のうち④の2件を採り直した(#14・#15)
```

質問に答えられない走らせ方で自分で立てた論点・基準には、行の末尾に `(未承認)` を添える(SKILL.md のゲートの注記)。

## 台帳本体(表)

**台帳本体は必ず Markdown の表で書く(F-001・2026-08-17)。** 箇条書き・見出しの羅列・散文で代替しない。
理由は体裁の好みではない: **納品物チェッカーは表が見つからないと中核の検査(全行リンク・必須列・入手状況の語彙・アクセス日)を実行できない**
(かつては、それでも「違反なし」と表示していた。いまは検査不能として合格にしない)。表で書かないと、一度も中身を見られていない台帳ができる。
1行目がヘッダー行、2行目が `|---|` の区切り行、以降が各文献の行——という素直な表にする(セル内の改行や結合セルを使わない)。
マスの中で行を分けたい所(要旨の箇条)は、本当の改行でなく `<br>` を書く(本当の改行は表を崩し、その行から後ろをチェッカーが読めなくなる。`<br>` は Markdown を整えて見せる画面で改行になる)。
**表の縦棒に全角の「｜」を使わない**(半角の `|` で書く)。全角の縦棒で区切った行は表として読めず、納品物チェッカー(ref-nohin-checker)が点検できないので、合格にならない。
学術文献の行と統計原表の行は**別々の表**に分ける(下記「統計原表行の追加メタ」)。

| 列 | 内容 | 必須度 |
|---|---|---|
| # | **台帳全体で一意**の連番(1から)。**空欄・重複を禁じる。表を割っても通しで続ける**(1つ目の表が#1〜#8なら次の表は#9から。表ごとに1へ戻さない)。uradori・ronbun-shippitsuへ渡すときの対応番号になる | 必須 |
| 書誌 | 著者・年・題・誌名・巻(号)・頁。**各文献の詳細/DOIページで確定したもののみ** | 必須 |
| 種別 | 査読論文/学会誌(査読不明)/紀要/学位論文/白書・報告書/統計原表(Excel・CSV)/書籍/業界資料/プレプリント。**「査読論文」と書けるのは下記「査読の確定手続き」を踏んだ行だけ** | 必須 |
| 言語 | 和/英=**本文言語**(主題ではなく本文が書かれた言語。海外事例を扱う和文論文は『和』)。和主英従モード時のみ。**和のみで充足したら列ごと省略可** | 条件付き |
| 発見経路 | DB名+検索語、または芋づる(例: CiNii「6次産業化 直売所」/「#3の引用文献より」) | 推奨 |
| リンク | 優先順: DOI/J-STAGE記事ページ(本文に最短)> 機関リポジトリ本文ページ > crid等の書誌ページ(補助)。**全行必須(鉄則)**。J-STAGE収録誌は**DOIとJ-STAGE記事直URLを併記**する(下記A-7) | 必須 |
| 入手状況 | 下記の語彙から | 必須 |
| 精読 | 要旨が**本文精読済み**か**抄録どまり**か。執筆(断定の粒度)・裏取り(照合の粒度)の両下流が参照する | 推奨 |
| 要旨 | 2〜3行。読めた範囲を明記(全文/抄録より)。**自分の言葉でまとめる。原文の文をそのまま使うなら「」で囲んで逐語だと示す**(下記「要旨の書き方」)。**原典に印字されている値と、台帳側が導いた値(合算・換算・推計)を混ぜない**(下記「導いた値の書き分け」) | 推奨 |
| 抜き書き | 要旨の元にした原文の1〜2文を「」で原文のまま囲み、場所を添える(例「…といえよう。」(本文 p.6「6. 終わりに」))。**要旨を本文か抄録から書いた行には必ず置き**、題名・書誌・目次だけから書いた行は「なし(書誌のみ)」と書く(下記「抜き書き」) | 条件付き |
| 用途タグ | 背景/方法/比較/反論——執筆のどこで使えるか。**4語のいずれかを必ず含める**(下記「推奨欄の下限」) | 推奨 |
| アクセス日 | 実アクセスした日付 | 必須 |

**1つの物理列を2つの必須概念に兼用しない。**必須の概念にはそれぞれ**別の列**を立てる。1つの列に2つの概念を詰めた表は、**その必須概念が「ある」とは数えない**。

**「#n」という書き方は台帳の行番号だけを指す(F-017・2026-08-17)。** 発見経路欄の「#3の引用文献より」は
**この台帳の3行目の文献から辿った**という意味である。検索結果の順位・DB側の通し番号など**別のものを #n で書かない**
(順位を書きたいときは記号を使わず語で: 「CiNii『農産物直売所』検索の上位3件目」)。
**その台帳に存在しない番号を参照しない**(7件しかない台帳に「#14」と書かない)。
下流のスキルはこの番号で対応表を作るので、番号が二つの意味を持つと突き合わせられなくなる。

## 書誌の項目ファイル(2026-10-20)

書誌欄は1つの文なので、機械には年・題名・頁・出版社の境目が分からず、項目ごとに照らせない。そこで書誌を項目に分けたファイルを台帳と同じフォルダに置き、**表の書誌欄はそのファイルからスクリプトが書く**(`scripts/shoshi.py`。手で2回書かないので、表とファイルが食い違わない)。

- ファイル名: `<台帳名>.shoshi.json`(台帳の JSON と同じフォルダ。チェッカー用の Markdown は作業用フォルダに作るが、項目ファイルは台帳の置き場に置き、チェッカーには `--shoshi` でこのパスを渡す)。行は台帳の # の番号(`n`)で対応する。台帳の全行を入れる(統計原表など項目に分けにくい行は `shurui: sonomama` と書誌欄の文 `shoshi` で入れる)
- 項目: `chosha`(著者名の並び。原典の表記のまま)・`nen`(年)・`dai`(題名の本題)・`fukudai`(副題)・`shi`(誌名。図書の章では収録した図書の名)・`maki`・`gou`・`peji`・`shuppan`(図書・報告書は必須)・`doi`・`kakunin`(書誌を確かめたページの `url` と日付 `hi`)。種類 `shurui` は ronbun(既定)・hon・sho・hokoku・sonomama
- **副題は `fukudai` に分けて書く**。登録機関は本題だけを持つことが多く(実測で台帳の3割)、本題と副題が1つの欄に混ざると、正しい題名が照合で食い違って見える
- 書誌欄の書き方はスクリプトが決める(論文= `著者(年)「題名：副題」誌名 巻(号), 頁`、図書= `著者(年)『書名』出版社`)。直すときは項目を `shoshi.py … tsuika` で直し、`daicho.py … kaku --w <作業用フォルダ>` で作り直す(`shoshi.py … kaku` は JSON の無い古い台帳の Markdown を直接書き換える命令で、新しい台帳では使わない)。書誌欄だけを手で直すと、チェッカーの段階B が「書誌欄が項目ファイルと食い違う」で止める
- チェッカーには `--shoshi` で渡す。DOI を持つ行は、著者名・誌名・巻(号)に加えて年・題名・頁・出版社も登録機関の記録と照らす。項目ファイルに書いていない項目(論文の出版社など)は照らさず、その数を申告に出す。照らし方と、それでも機械が見ない所は SKILL.md 工程5

## 推奨欄の下限(F-074・2026-08-17)

「推奨」の欄は**書くか書かないか**しか決まっておらず、同じ依頼でも回ごとに中身の濃さが大きく振れていた
(用途タグが4語のどれでもない自由語だけの回と、きちんと4語で書かれた回が入れ替わる)。**満たすべき下限を決める**:

- **用途タグ** — **背景/方法/比較/反論の4語のいずれかを必ず含める。**そのうえで補足を足すのは自由
  (例「背景(直売所の全国動向)」「比較・反論」)。**空欄や「—」で出さない**。
  4語のどれにも当てはまらない文献は、なぜ台帳に入れたのかを要旨か備考に書く
- **要旨** — 先頭の研究の種類と2〜4つの箇条。**最初の箇条で「何を対象に、どう調べた研究か」が分かること**が下限(下記「要旨の書き方」の形)。
  題名の言い換えだけで終えない。読めた範囲(全文/抄録より)と、導いた値かどうか(上記「導いた値の書き分け」)を必ず添える
  - **「(本文より)」も、本文を読んで書いた側の印である**(「(全文より)」「(ページ本文より)」と同じ)
- **探索記録** — 「未実施」と書いて終わらせない。**見つからなかった論点があるならブロックを立てて次の一手まで書く**、
  **無いなら「見つからなかった論点なし」と明記する**(上記「探索記録」の節)。
  ★**論点を名指ししないほうが記録がきれいに見える**という逆向きの誘惑がある。埋まらなかった論点を書き出すことが台帳の値打ちなので、
  **書き出した論点の数の多さを欠点として扱わない**

★この下限は**現状より少し上**を狙った線である(実運用17本では用途タグが4語だけで書かれた台帳は1本も無かった)。
「4語**のみ**」まで厳しくすると既存の台帳がほぼ全部一斉に違反になるので、**まず「含む」から始める**。

## 入手状況の語彙(入手性の軸・他スキルのラベルと非衝突)

run-uradoriの判定5語(裏付け等)・run-kikakushoの信頼性5種(仮・仮説・要検証・推論・確定)とは別軸(=文献が手に入るか)。混同しないよう専用語を使う:

- **全文OA** — 全文が無料公開(J-STAGEフリー・機関リポジトリ等)
- **抄録のみ** — 抄録は読めたが全文は未入手
- **有料** — 全文が有料(出版社サイト等)
- **学内限定** — 大学契約DBで読める見込み(学内認証はユーザーの領分)
- **未入手** — 書誌は確定したが本文にまだ到達していない

**確定手続き(2026-07-19検証イテレーション1で正典化)**: 全文OA・抄録のみのラベルは、**本文提供側ページ**(J-STAGE記事ページのアクセス種別表示〈フリー/オープンアクセス/認証あり〉・機関リポジトリの本文ページ等)への実アクセスで確定する。**CiNii・NDL等の書誌ページの記載(「リポジトリリンクあり」等)からの推定は禁止**——その場合は「未入手」+備考「リポジトリ本文リンクあり・未確認」とする。実際より読めている風への格上げはゼロ許容違反(検証イテレーション1のFAIL(不合格)3件は全てこれ)。

**精読フラグの運用(A-8・2026-07-20)**: **本文を全部読んで**要旨を書いたら「本文精読済み」、それ以外(抄録・書誌情報だけ、または本文の一部だけを読んで書いた)は「抄録どまり」を精読列に記す(2026-10-31 に「全部」を足した。冒頭と結びだけを読んで「本文精読済み」と書いた行が、4本の台帳の149行のうち24行あったため)。本文精読済みの行は要旨の先頭を「(本文より)」にし、一部だけ読んだ行は「(本文の1〜3節と結びより)」のように読んだ範囲を書く(本文の一部を名乗る印と「本文精読済み」の組は、言い過ぎである)。文字の取れない頁は頁の画像を見て読む(2026-10-31・D64): 画像だけの PDF を全頁読んだ行は「本文精読済み」で、印は「(本文の画像より)」(全部読んだ時の形)。文章は文字になったが表や図が崩れた頁は、その頁を画像で見て全部読めば「(本文より)」で「本文精読済み」。画像でも読めない頁が残る時だけ「抄録どまり」にし、読めなかった物を印に書く(「(本文の文章の全部より。図表は未読)」)。入手状況が「全文OA」でも、実際に本文を読んでいなければ「抄録どまり」であり、格上げしない。下流の使い分け——run-ronbun-shippitsuは「本文精読済み」の文献だけを原稿で引き、「抄録どまり」(書誌のみの行も含む)は原稿で引かずに、本文を読んでから使う候補として書き手に知らせる(ユーザーの決定 2026-11-01。書き手は、本文を読めていない文献を論文に使わないため)。run-uradoriは精読フラグで照合粒度(本文記述 vs 抄録記述)を決める。

## 導いた値の書き分け(F-076・2026-08-17)

要旨欄の出所ラベル(「(抄録より)」「(ページ本文より)」)は**どこまで読んだか**を表すものであって、
**そこに書いてあったのか、台帳側が計算したのか**は別の軸である。**この2つを書き分ける。**

- **原典にその数字が印字されている** → 「(ページ本文より)」等をそのまま使い、**原典の表記のまま**写す
- **台帳側が導いた(合算・平均・換算・推計・時点の推測)** → **「(台帳で合算)」「(台帳で換算)」のように導出であることを明記**し、
  何から導いたかを一言添える(例: 「都道府県別の一覧を台帳で合算して1,231」)
- **原典に無い基準日・時点を書かない。**一覧を数えた値なら「アクセス日時点の一覧より」と、いつの一覧かが分かる形にする

★実例(実測): 道の駅の全国件数「1,231」は原ページに合計値が印字されておらず**都道府県別の一覧を数えた値**だったのに、
当該原典を載せた台帳7本中5本が「(ページ本文より)」として書いていた。読み手はそれを一次資料の記載として卒論の背景章に写す。

文面の型は姉妹スキル **run-uradori** に既にある(「条件付き裏付け」「具体値の格上げ禁止」)。迷ったらそちらに合わせる。

## 要旨の書き方(F-022・2026-08-17)

**要旨は自分の言葉でまとめる。原文の文をそのまま持ってくるなら「」で囲み、逐語だと示す。**

これは新しい基準の発明ではなく、姉妹スキル **run-uradori** の同じ位置の列定義
(`run-uradori/references/daicho-format.md`「②は原文の要旨。③は「」付き逐語引用(取得原文からの転記のみ)」)に揃えるだけである。

- **「(抄録より)」は〈どこまで読んだか〉の表示**であって、〈著者の文そのものか〉までは言っていない。
  **この2つは別の軸である**(上の「導いた値の書き分け」と同じ形)
- 抄録の文から数語を落として繋いだだけのものは**自分の言葉ではない**。そのまま使うなら「」で囲む
  (実測: 抄録の第1文から2か所を削っただけで**34字が連続一致**していた台帳行がある)
- 逐語で引くのは**必要な範囲だけ**にする。要旨の全体を「」で埋めない(それは要旨ではなく転載である)
- ★**この欄は「推奨」である。**ここで決めたのは**これから書く台帳の下限**であって、
  既に納品した台帳を一斉に不合格にするものではない(納品物チェッカー(ref-nohin-checker)が要旨について見るのは、鍵括弧に入れた逐語が原典に在るか(段階C)だけで、それ以外の要旨の中身は検査しない)

### 形: 先頭に研究の種類を書いた箇条書き(2026-10-31・claude-harness の docs/user-decisions.md の D62)

要旨の書き方のクイズで、箇条書きと「文の先頭に研究の種類を置く形」がどちらも今までの文より選ばれ、ユーザーが2つを合わせた形に決めた(D62 の7枚目 問3)。

```markdown
(本文より)計量分析。<br>・全国の市区町村の空き家率を、国勢調査の人口と世帯の指標で重回帰分析した研究<br>・回帰式で調査の対象外の町・村の値を推定し、全市区町村を地図にした<br>・老年人口比率と単独世帯比率が空き家率を押し上げる
```

- 先頭は読めた範囲の印(「(本文より)」「(抄録より)」「(本文の1〜3節と結びより)」など)。続けて研究の種類を短い語で書き、「。」で区切る(例「事例研究。」「調査研究。」「計量分析。」「総説。」)。種類の語は2〜10字で、「研究」「調査」「分析」「報告」「論考」「総説」「資料」「研究書」「論集」「論文」「解説」「書評」「レビュー」「実験」「方針」「課題」のどれかで終える(後ろの4つは 2026-10-31 に足した。例「文献レビュー。」「質問紙実験。」「研究課題。」。D64)。「事例研究の抄録」「講演の要旨」「〜の予稿」のように、読んだ範囲を先頭の印と重ねて言う語にしない。読んだ範囲から種類が読み取れない時は付けない(推測で付けない)
- 箇条は2〜4つ(列の表の「2〜3行」は、この形の箇条2〜4つと読む)。`<br>・` で区切る(マスの中で本当に改行しない)。1つの箇条に1つのこと(何を対象にどう調べたか/何が分かったか/何を論じたか)を書き、箇条の終わりに「。」を付けない
- **最初の箇条で、何を対象にどう調べた研究かが分かるように書く**(何の研究かが最初の一文で分かる、とユーザーが今までの文を選んだ理由に書いた。D62 の4枚目 問3)
- **知られていない会社・団体の名前には、何者かを一言添える**(例「食品会社のカゴメ」。名前だけでは会社だと分かりにくい、とユーザーのメモ。D62 の4枚目 問3)

## 抜き書き(2026-10-31・claude-harness の docs/user-decisions.md の D62・D64)

要旨にまとめると、原文と意味がずれることがある。要旨の元にした原文の文を、原文のまま隣の欄に置き、読み手と確かめ役が並べて見られるようにする(D62 の4枚目 問1)。

- 台帳本体の表の、要旨の列の右に **「抜き書き」の列**を立てる(下の「書き方の見本」)
- **要旨を本文か抄録から書いた行は必ず置く**。題名・書誌・目次だけから書いた行は「なし(書誌のみ)」と書く
- 1〜2文。要旨のいちばん大事な箇条(何が分かったか・何を論じたか)の元になった文を選ぶ
- 形は `「原文」(場所)`。場所は、本文なら `scripts/nukigaki.py basho` が出した書き方(「本文 p.6」)に節の見出しを添える(「本文 p.6「6. 終わりに」」)。抄録なら「抄録」。画像だけの PDF の行(nukigaki.py が「本文を文字にできない」で止まる行)は、頁の画像から原文の字のまま書き写し、場所に「画像から書き写し」と添える(「本文 p.84・画像から書き写し」)。この印の抜き書きは機械では照らせないので、確かめ役が頁の画像と照らす(D64)
- **原文のまま写す**。言い換えない・語を足さない・誤字や誤変換に見える所も直さない(直すと言い換えになり、照合で止まる)
- 途中を省くときは「…」で区切る(区切りごとに、原文の中で順に照らす)。2段組の PDF で左右の段が1行に混ざる所も「…」で区切る
- 数で始まる所を切り出すときは、原文でその直前にある負号(−)ごと写す(負号を落とすと意味が逆になり、照合でも止まる)
- 原文の中の「」は、そのまま写す(全体を外側の「」で囲む)
- 本文から切り出した行は、**本文PDFの置き場をリンクの欄にも入れる**(`{"honbun": true}`。読み手と確かめ役が本文の文にすぐ行けるように。チェッカーの段階C も、リンクの欄の URL に当てて照らす。記事のページだけでは本文の文を照らせない)
- 照合: 書く時に `scripts/nukigaki.py basho` で、本文に原文のまま在るかを確かめる(「見つからない」と出た抜き書きは台帳に書かない)。見るのは「在るか」と在る頁までで、要旨の意味が抜き書きと合うかは見ない
- 要旨の箇条が抜き書きと原典に支えられているかは、確かめ役 assign-bunken-evaluator が別の文脈で読む(SKILL.md 工程5)

## 種別「査読論文」の確定手続き(F-019・2026-08-17)

**「査読論文」は掲載誌の見た目・知名度・学会名から推定してよい語ではない。**書誌・入手状況・精読と同じく、**このセッション内の実アクセスで確定してから書く**。

**確定に使える根拠(いずれか1つを実際に開いて見る)**:

- **掲載誌のトップ(刊行案内)ページの査読表示** —— J-STAGE の資料トップで ISSN(雑誌ごとの国際番号)の直後に出る「ジャーナル **査読** フリー」の帯。**最も安く確実**(→ wabun-db-guide.md の J-STAGE の技)
- 学会・発行機関の**投稿規程・査読規程**のページ(「投稿原稿は査読に付す」等の記述)
- 記事ページの**区分表示**(《論文》《原著》に対する《報告》《資料》の別)。ただし区分の意味は誌ごとに違うので、**これ単独では確定にしない**(他の根拠と併せて使う)

**根拠の残し方**: 発見経路欄または備考に**何を見て決めたかを一言残す**(例: 「誌トップの査読表示『査読あり』で確認 2026-08-17」)。**根拠が残らない行に「査読論文」と書かない。**

**確認できないときの退避語彙**: 断定せず **「学会誌(査読不明)」**(学会・研究会の刊行物だが査読の有無を確かめられなかったもの)を使う。**推定による「査読論文」への格上げは、入手状況の格上げと同じくゼロ許容違反**とする。

**確認ゲートとの関係**: 項目2で『査読論文のみ』が選ばれている場合、「学会誌(査読不明)」の行は**範囲外**である。台帳本体に載せず探索記録へ置き、なぜ確定できなかったかを書く(→ 上記「ヘッダーの宣言と本体の照合」)。

## 統計原表行の追加メタ(A-4・2026-07-20)

正典表は学術文献前提のため、種別「統計原表(Excel・CSV)」の行は書誌欄に調査名・表名を詰め込まず、次のメタを持たせる(下流のrun-excel-graph・run-uradoriが原表へ最短で戻れる):

- **調査年月** — e-Stat の統計表検索の結果一覧にある **『調査年月』**(いつ調べたか)をそのまま写す。**年代ゲートはこの調査年月で判定する**(→wabun-db-guide A-5)
  - ★**欄名を必ず書き添える**(F-109・2026-08-17)。結果一覧には『調査年月』と『公開(更新)日』という**似た欄が2つ**あり、同じ行でも数年ずれる。数字だけ書くと読む人がどちらを写したのか確かめられない。**書き方: 「調査年月: 2020年2月(e-Stat結果一覧『調査年月』欄)」**。参考として公開日も残すなら「公開(更新)日: 2022年3月」と**欄名つきで別に書く**(混ぜない)
  - ★旧版が指示していた **「提供年月」という欄は e-Stat に存在しない**(実証で出現0回)。**この名前で書かない**
- **statInfId** — e-Statの統計表ID(例 `000032143221`)。**これを台帳に載せると原表への再到達が1手**(`file-download?statInfId=<ID>&fileKind=0`でExcel直DL)。載せないと下流が検索からやり直しになる
- **fileKind** — 0=Excel(既定)/1=CSV(表により404あり)
- 書誌欄は「調査名・表名(設問番号・母数nがあれば)」。統計原表行は学術文献行と**別セクション/別ブロック**に分けて列のちぐはぐを避ける

## 選別の帳尻(論点ごとに1行)

どれだけ探し、どれだけ見て、何を採ったかを、論点ごとに1行で残す。どこまで拾えていそうかを読み手が判断する手がかりは、この数のほかに無い。台帳本体と書誌突合の1行の後、探索記録の前に、`## 選別の帳尻` の見出しで置く。探索記録の節の中には入れない(探索記録の中で「論点」から始まる箇条書きは、納品物チェッカーが論点の書き方の違反として数えるため)。

**この節はスクリプトが書く**: `scripts/daicho.py <台帳.json> kaku --w <作業用フォルダ>`(中で kensaku.py の数え方を使い、台帳の JSON に入れて Markdown と HTML に書く。JSON の無い古い台帳だけは `scripts/kensaku.py <作業用フォルダ> chojiri --daicho 台帳.md`)。数は検索の記録と候補の一覧(工程2 で `sagasu`・`te`・`tsuika`・`kime` が残した物)から数える。手で直さない(`kensaku.py … tashikame` が、一覧から数えた物と違う帳尻で止める。自己申告の数は、合っているかを誰も確かめられないため)。人と誌からたどった結果(中心と見た人と誌)は、帳尻ではなくヘッダーの「探し方(人と場)」の行に書き足す。

```markdown
## 選別の帳尻

数は候補の一覧からスクリプトが数えた(kensaku.py chojiri・2026-10-20T15:40:00+09:00)。一覧に入るのは、各検索で画面に出た上位の候補と、手で足した候補だけ。

- 論点1: 検索4本(手で記録 1)・ヒット計 160件(重なりを含む) / 一覧に出た 40件 / 見た 25件 / 採った 8件(#1・#3・#4・#7・#9・#12・#15・#20) / 落とした 17件(①重複 3・②範囲外 4・④別の対象 6・⑤論点に効かない 4) / 保留 1件(保留の割合 4%) / 未判定 14件
- 論点2(反論・限界): 検索3本(失敗・件数なし 1)・ヒット計 40件(重なりを含む) / 一覧に出た 12件 / 見た 12件 / 採った 0件 / 落とした 12件(④別の対象 7・⑤論点に効かない 5) / 保留 0件(保留の割合 0%) / 未判定 0件
- 論点3(歴史・研究史): 検索2本・ヒット計 60件(重なりを含む) / 一覧に出た 10件 / 見た 10件 / 採った 4件(#2・#5・#11・#18) / 落とした 6件(①重複 4・⑤論点に効かない 2) / 保留 0件(保留の割合 0%) / 未判定 0件
- 全体(重なりを除く): 検索9本(手で記録 1・失敗・件数なし 1) / 一覧に出た 58件(うち手で足した 3) / 見た 44件 / 採った 12件 / 落とした 31件 / 保留 1件 / 未判定 14件
```

- **見た = 採った + 落とした**(スクリプトが数えるので必ず合う)。「見た」は採否を決めた候補の数で、題だけで落とした物も入れる。**未判定**は一覧に出たが採否を付けていない候補で、多ければ「上位しか見ていない」と読み手に分かる
- **保留**は決め手の事実が言えないときだけ(本文が開けない・書誌が決まらない)。保留の割合が高いまま納品するときは、納品のチャットでその数と理由を言う(保留を逃げ場にしないため)
- 1つの文献が2つ以上の論点に効くときは、どの論点の「採った」にも行番号が入る(「採った」の合計は台帳の行数と合わなくてよい)。どの論点に数えるかを決め直すときは `kime … --ronten 1,3`
- 「ヒット計」は件数の表示があった検索だけを足す(件数の表示なし・失敗は足さず、本数を括弧に出す)
- 「全体」の行は重なりを除いた数で、見つけた → 見た → 採った の引き算になる

**落とした理由**は、次の順に見て最初に当てはまる1つを選ぶ(確かめやすく、人によって割れにくい物から並べてある。後ろほど判断が入る):

- **①重複** — すでに採った文献か、同じ文献の別の記録(別のDBの同じ論文・同じ内容の大会抄録)
- **②範囲外** — ゲートの種別範囲・年代範囲・言語の外
- **③確かめられない** — 文献ページ・DOIページを開けず、書誌を確定できない(SKILL.md 鉄則1)
- **④別の対象** — 適合の基準の対象・場所・時代から外れる(国・地域が依頼と違うことだけでは④にしない。依頼が地域を決めている時を除く。海外の事例にも比べる材料・先行研究として使える物があるため)
- **⑤論点に効かない** — 対象は合うが、どの論点の材料にもならない

④⑤で落とす前に、**比べる材料か土台の理論にならないか**を見る。隣の対象(依頼が小・中学校なら高校、依頼と違う国の事例)や、テーマの上位の分野の理論・研究動向は、落とさずに用途タグを「比較」「理論」にして採る(読み手は、比べる材料や考え方の土台として本文で使うため)。対象そのものが別の物(農業への参入の依頼に、漁業への参入)は④で落とす。

1件ずつの記録は作業用フォルダの候補の一覧(`kouho.jsonl`)に残り、台帳には数だけを書く(作業用フォルダは台帳と一緒に配らないので、件数が多くてもよい)。1件ごとに、題とURL・論点の番号・経路(どの検索から来たか)・採否・理由の番号・**決め手の事実**(30字まで)が残る。決め手の事実は、読み手が採否を確かめ直せる事実にする(例「④ 対象が韓国の農村」「② 2019年の刊行で範囲の外」)。「関係が薄い」「テーマと違う」のように理由の番号を言い直すだけの言葉は、確かめ直す手がかりにならないので書かない。探索記録の「見つけた候補・未採用」にも、同じ番号と決め手の事実で書く。

## 探索記録(再挑戦の起点)(必須・uradori段3で確定した標準搭載)

見つからなかった論点・薄かった論点がある場合、台帳の後に独立セクションで置く。備考に詰め込まない:


- **出版社が機械の取得を断った論文**(HTTP 401・403。英語の大手の出版社に多い。2026-11-02 に MDPI・Wiley・Taylor & Francis の3社とも 403): 次のとおりにする(ユーザーの決定 2026-11-02)

  4. 抄録は `kensaku.py <作業用フォルダ> shoroku --doi <DOI>` で取り(出どころの URL と一緒に作業用フォルダの `shoroku/` に残る)、抜き書きの場所は「抄録(OpenAlex の記録)」のように出どころを添えて書く

## 台帳の JSON(正本)と、スクリプトが作る HTML・Markdown(2026-11-01・claude-harness の docs/user-decisions.md の D67)

台帳の中身は JSON に持ち、人が見る HTML と、チェッカーと確かめ役が読む Markdown は `scripts/daicho.py` が毎回同じ形で作る。Markdown は機械の読み手(チェッカー・確かめ役)が使う写しで、ユーザーには渡さない(同じ中身なら AI が読む字数は Markdown のほうが JSON より少なく、作るのはスクリプトなのでトークンも掛からない。D67 の 5)。
